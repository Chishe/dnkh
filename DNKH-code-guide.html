01 / OVERVIEW

ภาพรวมสถาปัตยกรรม

คำขอหนึ่งครั้งเดินทางผ่าน 5 ส่วน

Fastify เป็นตัวกลางระหว่าง Browser กับฐานข้อมูล หน้าเดิมยังใช้ไฟล์ .php เป็นแม่แบบ HTML แต่ไม่มีการรัน PHP บนเซิร์ฟเวอร์อีกแล้ว

1Browser

ผู้ใช้เปิดหน้า ค้นหา หรือส่งฟอร์มผ่าน URL เดิม เช่น /traceability/brazing_nb.php

2Fastify

src/server.js เปิดพอร์ต และ src/app.js ประกอบระบบทั้งหมด

3Route

src/routes/ ตรวจ URL แล้วเลือกว่าจะส่งหน้า HTML หรือข้อมูล API

4Service

src/services/ เตรียมคำสั่ง SQL และประมวลผลข้อมูลทางธุรกิจ

5MySQL

src/db/pools.js ใช้ connection pool ติดต่อฐานข้อมูล packing_dnkh และ dnkh

จุดสำคัญ: นามสกุล .php ถูกเก็บไว้เพื่อให้ลิงก์และ Bookmark เดิมยังใช้ได้ แต่โค้ดฝั่งเซิร์ฟเวอร์ทำงานด้วย Node.js/Fastify ทั้งหมด
02 / FILE MAP

แผนที่ไฟล์

แต่ละโฟลเดอร์รับผิดชอบอะไร

แยกส่วนรับคำขอ การประมวลผล ฐานข้อมูล และหน้าจอออกจากกัน เพื่อหาจุดแก้ไขได้เร็วและลดผลกระทบข้ามส่วน

ไฟล์ / โฟลเดอร์หน้าที่
src/server.jsจุดเริ่มต้นของโปรแกรม สร้างแอปและเปิดรับคำขอตาม HOST/PORT
src/app.jsตั้งค่า Fastify, form body, route, static files, timeout และตัวจัดการ error กลาง
src/routes/pages.jsค้นหาไฟล์หน้าเดิมอัตโนมัติ รองรับทั้ง URL แบบมีและไม่มี .php แล้วส่ง HTML กลับ
src/routes/api.jsรวม API สำหรับกราฟ เครื่องจักร Helium Leak, Lane และ LL Patrol
src/services/dashboard.jsSQL และกติกาของหน้าค้นหา Traceability รวมถึงหน้ารายงานตามวันที่
src/services/machine.jsSQL และกติกาของ Machine Condition, Alarm, Helium และการบันทึก Patrol
src/db/pools.jsสร้าง MySQL connection pool สองชุดและนำกลับมาใช้ซ้ำ ลดเวลาต่อฐานข้อมูลใหม่ทุกคำขอ
src/lib/html.jsอ่านแม่แบบหน้าเดิม รวม partial, ใส่ข้อมูลลง HTML, escape ค่า และเติมเวอร์ชันให้ CSS
traceability/ · trendcontrol/แม่แบบหน้าจอและ JavaScript ฝั่ง Browser โครง UI เดิมยังอยู่ที่นี่
partial/ · style.cssHeader, Sidebar และชุดสี/รูปแบบที่ใช้ร่วมกันทุกหน้า
ecosystem.config.jsกำหนด PM2 ให้รันแอปชื่อ dnkh-dashboard เพียง 1 instance บนพอร์ต 8800
test/ทดสอบ route, HTML renderer, ความปลอดภัยของ static files และการตั้งค่า PM2
03 / CODE FLOW

อ่านโค้ดตามลำดับ

4 จุดหลักที่ทำให้ระบบทำงาน

ตัวอย่างด้านล่างย่อจากโค้ดจริง เน้นความสัมพันธ์ระหว่างไฟล์มากกว่ารายละเอียดทุกบรรทัด

A · Start server

เปิด Fastify ตามค่าที่กำหนด

src/server.js สร้างแอปเพียงครั้งเดียวและเปิดพอร์ตจาก config

// src/server.js
const app = buildApp();
await app.listen({
  host: config.host,
  port: config.port // 8800
});

B · Register routes

ประกอบหน้า API และไฟล์ static

src/app.js เป็นศูนย์กลางตั้งค่าระบบ และป้องกันไม่ให้ source code ถูกเปิดเป็น static file

// src/app.js
app.register(formbody);
app.register(require('./routes/api'));
app.register(require('./routes/pages'));
app.register(fastifyStatic, {
  maxAge: '1h',
  allowedPath: safePublicFile
});

C · Query data

ใช้ parameter แทนการต่อ SQL

Service รับค่าจาก route แล้วส่ง SQL พร้อม parameter เข้า pool ลดความเสี่ยง SQL injection

// src/services/dashboard.js
const [rows] = await packing.execute(
  'SELECT * FROM `nb_1` WHERE `nb_pd` = ?',
  [selectedDate]
);
return rows;

D · Render legacy UI

ใส่ข้อมูลลงแม่แบบอย่างปลอดภัย

escapeHtml() แปลงอักขระพิเศษก่อนนำค่าจากผู้ใช้หรือฐานข้อมูลไปแสดงใน HTML

// src/lib/html.js
function escapeHtml(value) {
  return String(value ?? '')
    .replaceAll('&', '&amp;')
    .replaceAll('<', '&lt;')
    .replaceAll('>', '&gt;');
}
04 / REQUEST

ตัวอย่างการทำงานจริง

เมื่อเปิดหน้า NB Brazing

ตัวอย่างนี้แสดงว่าชื่อไฟล์เดิมเชื่อมกับ route และฐานข้อมูลใหม่อย่างไร

Browser ส่ง GET

เปิด /traceability/brazing_nb.php?selected_date=2026-09-23

Page route รับคำขอ

pages.js จับ route จากไฟล์ traceability/brazing_nb.php และส่งวันที่ไปยัง service

Service อ่านฐานข้อมูล

dashboard.js เลือกตาราง nb_1 และคอลัมน์ nb_pd จากแผนที่ datedPages

Renderer สร้าง HTML

html.js อ่านแม่แบบ ใส่แถวข้อมูล และเติม ?v=... หลัง style.css เพื่อป้องกันแคชเก่า

Fastify ส่งผลลัพธ์

Browser ได้ HTML ที่หน้าตาเหมือนเดิม โดยไม่ต้องติดตั้งหรือประมวลผล PHP

06 / OPERATIONS

รันและตรวจสอบระบบ

คำสั่งที่ใช้ประจำ

รันคำสั่งจากโฟลเดอร์ Dashboard หรือใช้ไฟล์ BAT สำหรับ Startup ซึ่งจะเปลี่ยน path มายังโฟลเดอร์ของตัวเองให้อัตโนมัติ

start-dashboard-pm2.batไฟล์สำหรับวาง Shortcut ใน Windows Startup
npm run pm2:statusดูว่าแอปออนไลน์และมีเพียง 1 process
npm run pm2:restartรีสตาร์ตหลังแก้โค้ดหรือ Environment
npm run pm2:logsดู log เมื่อหน้าเว็บหรือฐานข้อมูลมีปัญหา
npm run checkตรวจ syntax ของไฟล์เริ่มต้น
npm testรัน automated tests ทั้งหมดก่อนนำขึ้นใช้งาน
Health check: เปิด http://localhost:8800/api/health หากระบบปกติจะได้ JSON ที่มี status: "ok" และ runtime: "fastify"
07 / RECOVERY

แก้ปัญหาเบื้องต้น

อาการที่พบบ่อยและจุดตรวจ

แยกก่อนว่าปัญหาเกิดที่ URL, Fastify, PM2 หรือ MySQL จะช่วยลดเวลาหาสาเหตุ

404 NOT FOUND

ชื่อ route ไม่ตรงกับไฟล์จริง

ตรวจชื่อไฟล์ใน traceability/ หรือ trendcontrol/ เช่นหน้าที่ถูกต้องคือ brazing_nb.php ไม่ใช่ nb_brazing.php

DATABASE ERROR

หน้าเปิดได้แต่ไม่มีข้อมูล

ตรวจว่า MySQL ทำงานอยู่ ค่า Host/Port ถูกต้อง และฐานข้อมูล packing_dnkh กับ dnkh เข้าถึงได้

2 PROCESSES

PM2 รันมากกว่าหนึ่ง instance

ตรวจ ecosystem.config.js ต้องเป็น exec_mode: "fork" และ instances: 1 จากนั้นใช้ npm run pm2:restart

SAFE CHANGE

ก่อนนำเวอร์ชันใหม่ขึ้นใช้งาน

รัน npm run check และ npm test ตรวจหน้าใช้งานจริง แล้วจึง restart PM2 เพื่อลดผลกระทบกับผู้ใช้
